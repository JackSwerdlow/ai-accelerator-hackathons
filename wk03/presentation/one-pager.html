Principles that made it work

  • 1Guardrails first. Agent identity, a shared-repo git workflow, and "log in the same commit as the work" paid off the moment a second agent pushed.
  • 2Plan until the contracts are boring. A flat state object, one pure eligibility() function, one generic question page — settled before parallel coding began.
  • 3Fresh subagents review fresh code. Separating implementer / spec / quality reviewers surfaces defects an author can't see in their own work.
  • 4Verify the feature, not just the code. Tests are necessary; a browser run is proof — the automated E2E suite's 320px check caught a real WCAG reflow bug.
  • 5Record the why of every change. "What you changed + why" is where the engineering judgement — and the auditability — actually lives.
  • 6Let strong proposals compete. Two rival plans were kept side-by-side, their trade-offs captured, then chosen deliberately — not by default.
