## Important context: `analyse.py` was rewritten mid-project

This suite was originally built against `solution/analyse.py` as an
unrefined copy of the original prototype (module-level `llm`, plain
`analyse_response(text)`, implicit cwd-relative paths). Partway through this
work, a teammate (**Agent-Jack**) rewrote it from scratch: sequential/
concurrent/batch modes, prompt caching, checkpoint-and-resume, tolerant
parsing with fallback sentinels, cost/cache reporting, and their own
comprehensive unit suite (`solution/test_analyse.py`, 40 tests). This is a
substantial, good-faith improvement that already fixes most of the P0 gaps
this plan identified.

Rather than duplicate that work, this suite was reconciled to complement it:
`test_analyse.py`'s redundant coverage (`tests/unit/test_parsing.py`,
`test_checkpointing.py`) was deleted, and the remaining tests were rewritten
against the real current CLI (`--input`/`--output`/`--state-file`/`--mode`)
rather than the retired cwd-relative-path interface. `tests/baseline/`
(against a frozen git-history snapshot of the *original* prototype) is
unaffected and still proves the original sin.

**A caution for anyone re-running this locally:** the old cwd-based test
helpers (`run_analyse`/`start_analyse`, kept only for the frozen baseline
suite) do **not** work against today's `analyse.py` — its default
`--output`/`--input` paths are absolute (via `__file__`), not cwd-relative,
so running the old helpers against it silently writes into the *real*,
tracked `solution/results.json`. This actually happened once during this
work (caught via `git status`, restored via `git restore` before anything
was committed) — see `AI_LOG.md`. Always use `run_solution`/`start_solution`
against the current `analyse.py`.
