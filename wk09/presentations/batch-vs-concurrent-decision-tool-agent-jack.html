Real numbers from running the 40-row sample through all three modes on analyse.py (2026-07-15). Batch and concurrent produce the identical analysis — they differ only in speed and price. Batch is cheaper, never faster; concurrent is fast, at full price.

Where the money actually goes

A fair comparison adds three things no per-token price shows on its own.

API cost

Tokens × price per request. Batch is billed at 50% off; sequential and concurrent pay the full token rate.

Cost of waiting

A business cost, not wages — blocked downstream work or an SLA penalty per hour until results land. Applies to the API modes; set it to £0 for a job nobody's waiting on.

Manual — staff time

The do-nothing-with-AI baseline, and the only place staff wages count: pay people to read and tag each response by hand.

The trade

Batch trades speed for price. It wins when nobody's waiting; it loses the moment the delay costs more than the token saving.

What's hardcoded (and why)

  • 50% batch discount — a fixed industry constant (Anthropic, OpenAI, Google all use it).
  • Staff wages are charged to Manual only. The API modes pay for tokens plus the cost of waiting — never employee time.
  • Batch time is treated as ~flat (async SLA), not linear in volume — unlike concurrent, which scales with the number of waves.
